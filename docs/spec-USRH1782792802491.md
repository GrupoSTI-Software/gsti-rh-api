## 3. Modelo de datos

Sin tabla nueva. Consulta derivada:

```
FROM employees e
WHERE e.business_unit_id IN :tenantScope
  AND e.employee_deleted_at IS NULL              -- solo activos (baja lógica)
  AND e.employee_work_schedule IN ('Remote','Hybrid')
  AND e.employee_telework_percentage > 40        -- 5.1.f estricto
PRELOAD person (identificación), position (puesto),
        teleworkLocations (lugares activos, fijo pactado primero)
```

## 4. Contrato de API

```
GET /api/nom037/telework-workers?search=&page=&limit=
200 {
  type: "success", title, message,
  data: { teleworkWorkers: { meta, data: [ {
    employeeId, employeeCode, fullName, position, workSchedule,
    teleworkPercentage, workplaces: [ { locationType, address,
    isFixedAgreed, hasInternet, hasAdequateEquipment } ] } ] } }
}
403 { type:"error", key:"sin-permiso", code:"TWK.AUTH.001" }
```

- Sin acciones de escritura: la vista es derivada.

## 7. Criterios de aceptación (gherkin del refinamiento)

```gherkin
Característica: Listado de teletrabajadores 5.1 (vista derivada)

  Escenario: Solo entran los de más del 40% remoto
    Dado un empleado activo al 60% y otro al 40%
    Cuando consulto GET /api/nom037/telework-workers
    Entonces el de 60% aparece y el de 40% NO (umbral estricto)

  Escenario: El listado refleja el estado actual
    Dado un empleado que aparecía al 50%
    Cuando su porcentaje baja del umbral y recargo
    Entonces ya no aparece

  Escenario: Excluye bajas
    Dado un empleado dado de baja con 80%
    Entonces no aparece

  Escenario (aislamiento): No se ve gente de otra empresa
    Dado un teletrabajador de la empresa B
    Cuando un usuario de la empresa A consulta
    Entonces no aparece

  Escenario (permiso): Sin permiso no consulta
    Dado un usuario sin permiso del módulo
    Entonces recibe 403 { key:"sin-permiso", code:"TWK.AUTH.001" }
```
